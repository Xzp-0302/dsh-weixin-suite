# 更新与故障恢复

当前版本 0.1.0-rc.3。之前实验版本号 0.2.0-rc.1 已按发布者要求撤回。

## rc.1 / rc.2 更新失败修复

旧更新器在访问原生安装器之前，先从 raw.githubusercontent.com 读取清单。2026-10-29 在用户机器复现该域名连接超时，而同一提交的 api.github.com 内容接口返回 200；因此安装日志中没有新记录，页面只显示 failed。rc.3 改为 GitHub API 内容接口，页面展示阶段和清理后的错误原因。旧版本需要先通过 DSH 原生插件管理或 CLI 安装修复版，之后再使用插件内更新。

## 日常更新

打开微信助理 → 设置 → 插件更新，点击检查已发布版本，选择 GitHub 标签，再确认更新。无需手动卸载。仅显式点击时访问固定的 GitHub 仓库；选择固定到标签对应提交，避免可变分支导致版本识别不明确。不会自动更新或运行任意安装命令。

参考 DSH 的原生更新入口只接受 npm registry 包，Git 包不能直接走 updateBundle。本插件因此复用其 listBundles/removeBundle/installBundle，自动停止旧版、替换包，失败时尝试恢复原来源。这个内部替换与原生更新采用相同流程；不会删除本插件的独立微信账号、运行状态、页面设置和附件目录。当前候选版首次迁移仍需安装这个修复版本，之后可使用新增页面更新。

GitHub 标签删除/重建以及版本号倒退时，请按标签及发布说明选择，不以旧实验编号判断新旧。更新前先停止任务、取消扫码；保存未提交的设置。更新会卸载当前页面，操作不等待自己的卸载清理，避免 HMR 死锁。具体结果与网络失败诊断以 DSH 插件管理为准；回退同样需要原安装来源可访问。

## 旧版重复注册

旧版未收集 tools.register/systemPrompt.section 的 disposer，热卸载后工具仍留在 agent 中。修复版明确 yield 每个返回值，按 agent 和插件两个生命周期清理；不靠跳过重名注册掩盖仍引用旧 channel 的工具。

首次迁移请保存任务后完整退出 DSH（含托盘进程），再打开一次。只刷新页面不能清除旧进程泄漏。不需要删账号、重扫微信或复制 node_modules 临时补丁。用户由其他模型修改的已安装副本不在本次修改范围；更新会以本仓库代码替换。
