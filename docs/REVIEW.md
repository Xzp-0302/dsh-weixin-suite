日期：2026-10-27 至 2026-10-28。初版：0.1.0-rc.1；当前交付：0.2.0-rc.1 候选源码。

按用户要求未执行单元测试、集成测试、Harness 安装加载、二维码登录、微信收发或手机端验证。未安装依赖、未发布到任何市场。审查由同一开发会话多轮完成，没有委派子智能体。

## 第一轮：Harness 接口与生命周期

对照固定参考 Harness 源码核对 Cordis effect、Agent create/resume、preset、原生工具 schema、审批 waterfall、提问、session/event 和取消接口。

已修正：

- Cordis 内层 effect 没有返回 disposer，可能导致注册或卸载失败。
- 卸载顺序需要先取消任务，再释放 Agent 作用域的工具；关闭方法改为幂等。
- 恢复会话须优先挂载会话记录的 preset，避免配置变化意外切换工具集。
- Agent 身份校验使用当前注册对象，避免只凭旧 session ID 判定所属。
- setup 阶段尚未发布 Agent，提示词所属判断不能依赖 live registry。
- 工具结果的 callId/isError 在 message 内，修正结果状态消息字段。
- whenIdle 本身不能证明任务成功，改为结合持久化 turn/end reason 判断。

## 第二轮：并发、队列与恢复

已修正：

- /批准、/回答 等控制消息不能先以普通 queued 状态入队，避免被并发 drain 当任务执行。
- 保留所有未决任务，清理完成记录时不能用整体 slice 丢掉旧的待办。
- 状态写盘失败后停止接收和驱动任务，避免无记录执行后自动重放。
- 任务取消信号传递到创建/恢复 Agent、网络、上传和转换链路。
- 重启把未结束任务记为中断，恢复 Agent 时清除旧 inbox，禁止隐式重放；人工 /重试 仍可能重复已发生的副作用。
- 文件发送结果未知不自动重发；已获得 accepted 的操作不能在保存失败后被错误改写为 failed。
- 定时提问的框架超时原因保持不变，并保存补答编号；新会话清理旧问题入口。

## 第三轮：文件、状态与交付

已修正与核对：

- 独立状态目录设置所有权标记，不接受非空的其他程序目录，也拒绝现有桥接的状态目录名称和符号链接。
- 账号/私聊数量、本地文件大小、消息/附件数量、任务队列和引用缓存设置边界。
- 文件发送核对真实路径、允许目录、普通文件属性及读取前后变化；禁止发送私有凭证目录。
- CDN URL 限定微信可信域，拒绝凭证、非 HTTPS 和重定向；下载限量，校验解密、长度及 MD5。
- SILK 编解码放到可取消 Worker，避免 CPU 编解码阻塞 Harness；FFmpeg 使用 argv 和管道，不经过 shell。
- 核对 Loader 的按 id 覆盖语法、组合包入口、原始图标、中文/英文元数据和 MIT 第三方声明。
- 加入需求方案、能力矩阵、验收清单、发布指南与市场索引生成脚本。
- 读取运行状态前验证账号、路由、收件队列和发送记录；转交 Harness 附件前再次有界读取，避免下载后路径被替换。

## 生命周期修正与版本重置（2026-10-28）

用户实际验收发现 weixin_send 重名。前次声称所有嵌套注册自动归入外围 effect 的判断错误；Cordis 仅收集明确返回或 yield 的 disposer。现在 registerTools 为 generator，外围 yield*，prompt section 同样 yield。同步返回空值的 disposer 通过 Promise.resolve().then 调用；插件退出等待全部清理。已对照 vendor/cordis/src/fiber.ts 和 dsh-scope/store.ts 静态检查异常回滚及双重归属。

新增 Git 更新采用 DSH 原生管理器替换/回退，不复用旧 channel，也不绕开同名冲突。查询模型按需进行，仅名称和 ID 进入页面。使用已核对的主题变量替换亮色回退；增加说明与输入边界。版本号按用户要求重置为 0.1.0-rc.1。以上均待用户实际加载与功能验收，未执行测试。
